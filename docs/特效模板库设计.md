# 特效模板库设计

设计日期 2026-11-18 · Windows 本地部署

## 1. 产品目标

把一套可复用的特效工程作为一个模板管理。用户可以拖入项目目录，也可以从 MOV、Houdini 或 Nuke 工程进入同一套导入流程，确认项目边界和保留的文件后发布。之后通过多个标签找到效果、查看 MOV、下载所需版本，或把模板库完整恢复到另一台 Windows 电脑。

当前按**单机维护、本机磁盘保存素材、Houdini 和 Nuke 优先**设计。一个导入目录默认对应一个模板，目录里可以有多个入口工程。若一个目录里混放了不同效果，导入时先选择其中一个子目录或显式选择要归档的工程和文件。首版保留本地部署方式，存储接口留出后续接入共享存储的空间。

## 2. 界面和操作

参考 Eagle 的浏览效率，采用自己的界面视觉和信息层级。首页以标签筛选、模板封面和快速预览为主。模板详情随选中的版本切换，显示可用工程、依赖、大小和恢复状态。 [Eagle 产品演示](https://eagle.cool/) · [Prism Project Browser](https://prism-pipeline.com/docs/latest/general/Project%20Browser/)

| 区域 | 主要操作 |
| --- | --- |
| 模板库 | 搜索框、标签筛选、按软件筛选、封面网格和最近导入。列表只读取缩略图和索引数据，打开详情后再加载预览视频。 |
| 模板详情 | 播放 MOV 对应的预览，切换版本，查看工程入口、依赖树和缺失项。EXR 序列按一个条目展示帧号范围、实际帧数、缺帧和体积。 |
| 导入预检 | 展示目录树、识别到的工程入口、预计占用，以及每条自动筛选的原因。可批量勾选、恢复排除项、指定主预览。 |
| 任务中心 | 查看扫描、复制、优化、打包、恢复和 AI 分析进度。显示失败原因、可重试步骤和产物位置。 |
| 设置与恢复 | 首次配置存储目录、数据库连接和备份计划。单套模板提供精简包和完整模板包，库管理提供仅数据库和完整库备份，导入前列出内容和恢复结果。 |

标签支持用户创建多个标签并批量赋给模板。多选标签默认匹配**全部**，可切换为匹配**任一**。用户可以从「爆炸」「烟尘」「写实」直接组合搜索，也能用模板名称补充查找。标签作用于模板，版本变化时继续沿用。人工录入与已采纳的 AI 标签参与正式检索。

## 3. 技术选型与模块边界

| 层 | 选型和理由 |
| --- | --- |
| 桌面端 | **Electron + React + TypeScript + Vite**。Windows 用户可从资源管理器拖入目录，也可通过原生目录选择器导入。Electron 主进程通过受限 IPC 与界面通信，统一处理本机文件选择、流式传输和打开工程。渲染进程只接触窗口所需的数据和操作。 [Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model) · [本地文件路径 API](https://www.electronjs.org/docs/latest/api/web-utils) |
| 本地后端 | **Node.js LTS + TypeScript + Fastify**，以独立 Windows 服务账号运行。首版在本机回环地址提供版本化 API，由 Electron 主进程代理访问。桌面端持有受 Windows ACL 保护的本机访问凭据。服务负责数据库、归档目录、长任务和文件输出。Windows 服务可由 WinSW 托管。 [Fastify 文档](https://fastify.dev/docs/latest/) · [WinSW](https://github.com/winsw/winsw) |
| 数据库 | **PostgreSQL 18 + node-postgres + 版本化 SQL 迁移**。可接入本机现有 PostgreSQL 实例，单独创建应用库和应用账号。标签检索用关系表和索引，任务状态也持久化在 PostgreSQL；首版用一个限并发的任务执行器。 [node-postgres 事务](https://node-postgres.com/features/transactions) |
| 文件 | **NTFS 受保护目录**，按模板和版本保存文件及归档路径映射。通过同一个应用服务访问，后续有共享存储需求再实现对应的存储适配。 |
| 媒体 | **FFmpeg/ffprobe** 生成通用视频预览和读取媒体信息，**OpenImageIO/OpenEXR** 做 EXR 探测和转换，**OpenColorIO** 负责从线性或 ACES 素材生成正确的显示预览。发布前在 Windows 上固定并验证工具版本、编解码能力和分发许可。 [FFmpeg 过滤器](https://ffmpeg.org/ffmpeg-filters.html) · [OpenImageIO 工具](https://openimageio.readthedocs.io/en/v2.2.19.0/oiiotool.html) · [OpenColorIO](https://opencolorio.readthedocs.io/en/latest/) |

模块按职责组织为 `desktop`（界面与本机交互）、`service`（应用服务与任务）、`contracts`（请求、响应与包清单格式）。服务内按模板、导入、媒体、标签、备份划分。扩展点集中在 **存储访问、工程依赖扫描、AI 识别**。缩图、编码和压缩在子进程或后台任务中限并发执行，任务记录输入版本、输出和错误，重启后可继续或安全重试。

归档目录由服务账号持有写权限，日常桌面账号通过应用导入与导出。拖入的私有目录由 Electron 主进程以当前用户权限扫描文件列表，按已确认的清单把文件流传给服务。服务校验文件路径、大小和哈希，写入暂存区，无需给服务账号开放用户的整个制作盘。下载包或预览也按流读取，大文件无需载入界面或服务的整块内存。管理员仍可通过系统权限维护目录。

视频播放走 Electron 的内部媒体协议，主进程按版本和媒体 ID 转发请求，支持按字节范围读取，以便播放拖动进度条。界面无需获取真实磁盘路径或服务连接凭据。 [Electron 自定义协议](https://www.electronjs.org/docs/latest/api/protocol)

### 3.1 首次配置

1. **选择素材库目录。** 向导显示磁盘可用空间，检查目录是否在本机 NTFS 上、是否已绑定到其他模板库、服务账号是否可读写。已有受管理的库走「连接现有库」或「恢复备份」。需要创建受保护的子目录和设置 ACL 时，由管理员安装流程完成。
2. **连接数据库。** 输入主机、端口、数据库名和账号凭据，测试连接、应用库标识和必需权限。可使用事先创建的专用应用库。创建库和初始配置由安装管理员或用户指定的初始化账号执行，日常服务使用应用账号。开发阶段复用已确认监听 `127.0.0.1:5432` 的 PostgreSQL 18 实例，在其中另建开发库，例如 `vfx_templates_dev`。连接凭据保存在仅授权账号可读的本机配置中，导出包和日志不带密码。
3. **绑定与检查。** 用同一个库 ID 绑定数据库和素材目录，配置通过后再打开模板库。续用现有库时校验双方 ID。改存储路径使用迁移或恢复流程，禁止直接切换到任意有内容的目录。
4. **设置定时备份。** 选择备份位置、本地执行时间和保留份数。建议默认每天 03:00、保留最近 14 份成功备份，可调整或关闭。用户确认任务设置后启动计划。

## 4. 目录导入与文件筛选

### 4.1 从目录或文件开始

| 拖入内容 | 行为 |
| --- | --- |
| 项目目录 | 用拖入的目录作为候选根目录。先识别根目录内的工程和预览，再列出下层素材。如果同一目录下有多个镜头或多个无关工程组，用户选定要导入的范围。 |
| Houdini 或 Nuke 工程 | 将拖入的文件选为主工程，先检查所在目录。借助工程引用、同一镜头或效果名称、相邻目录推断项目根和配套工程。如果工程位于 `scenes/` 等子目录，可以向上少量检查候选目录，只在用户确认根目录后递归扫描。 |
| MOV | 将拖入的文件作为主预览候选，先在同级目录找名字同组的 HIP/NK，必要时建议上一级。找不到工程时可手动指定项目目录或先存为草稿。 |
| 多个文件 | 同一个候选根目录下的 HIP、NK、MOV 放在同一次导入中。属于不同目录或名字明显不成组时分开确认。 |

默认建议**直接拖项目目录**，用户最容易表达归档范围。通过单个文件导入时，界面先显示建议根目录、匹配到的工程和预览，并允许改选。根目录判断不明确时请用户选目录，避免递归扫到整季项目、用户主目录或盘符根。正式模板需要至少一个可选定的 HIP 或 NK 工程，以及一个指定或生成的主预览 MOV。两种工程、缓存、序列、HDA 和贴图按每套模板实际内容收录。

### 4.2 类型识别与依赖判定

**工程消费引用优先，其次是文件类型和命名规律，目录名只作提示。** 同一个目录可以同时包含几类素材。扫描结果保留判断依据，按「已确认」「建议保留」「待确认」「建议排除」展示。用户可调整主入口、用途和归档范围。确定被工程读取的文件默认保留，写出节点的目标路径作为产物线索，是否打包现存输出由用户确认。

| 文件或目录 | 判定信号与行为 |
| --- | --- |
| Houdini / Nuke | `.hip`、`.hiplc`、`.hipnc` 是 Houdini 工程候选，`.nk` 是 Nuke 工程候选。按共同的镜头和效果名分组，允许同组各自有入口。以 `~` 结尾的编辑器备份默认排除。 |
| ABC / 几何缓存 | `.abc` 明确标为 Alembic。`.fbx` 标为几何或动画资产，按工程引用和位置识别用途。兼容 `.bgeo.sc`、`.vdb` 等。同一目录可兼有 ABC、FBX 和其他类型，按文件或序列清单收录。 |
| 渲染序列 | 将同目录内的 `.exr` 等图像按文件名前缀、数字位置及位数、数字后的后缀和扩展名分组。结合 `$F4`、`%04d` 等工程路径占位符确认，记录实际帧范围及缺帧。只有一个文件且没有帧引用时先显示为单图或待确认。 |
| HDA | 识别 `.hda`、`.hdalc`、`.hdanc`、`.otl` 等 Houdini 资产库。可位于任意目录，按工程资产定义匹配，未能确认依赖关系时展示候选。 |
| 贴图 / HDRI | 优先按材质节点引用或 `<UDIM>` 识别，再结合 `tex`、`textures`、`hdr` 等目录提示。`1001`、`1002` 既可能是帧号也可能是 UDIM，只有数字时请用户确认。 |
| MOV | 将 MOV 列为预览候选。拖入的 MOV 优先作为主预览；目录导入时优先推荐和主工程效果名一致的 MOV。其他 MOV 若被工程读取则保留，也可以标为参考视频。 |

序列默认按实际文件分组，预期帧范围优先用工程读取范围或用户设置。版本数字（如 `v01`）仍属于序列名。如果文件名同时带帧号和分块号，保留原命名并让用户确认哪段数字是帧号。 [SideFX UDIM](https://www.sidefx.com/docs/houdini/solaris/udim.html) · [Houdini 资产库](https://www.sidefx.com/docs/houdini/assets/install.html) · [Nuke 文件 API](https://learn.foundry.com/nuke/developers/11.1/pythonreference/nuke-module.html)

**附件实例。** `EP04_seq01_sc073a_efx_v01.hip` 与同名 `.nk` 推荐为同一模板的两个入口，`EP04_seq01_sc073a_efx_ck_v001.mov` 推荐为主预览，`EP04_seq01_sc073a_ANI_ck.mov` 列为参考候选。`backup/` 和 `.nk~` 默认排除；`abc/`、`geo/`、`render/`、`hdr/`、`tex/` 都逐文件扫描。截图只显示项目根目录，内部文件用途由真实内容和工程引用确认。用户从任一入口文件拖入时，预检应给出同一项目根和这组候选。

### 4.3 预检与发布

1. **列出文件。** 本地扫描生成文件树、序列、主工程和 MOV 候选。工程载入前先用文件规则给出结果，深扫描失败时依然可人工完成导入并保留未验证标记。
2. **识别依赖。** Houdini 和 Nuke 适配器读取选定工程的文件引用，解析 `$HIP`、`$JOB`、帧占位符和可确定的路径。动态表达式、插件路径和无法解析的引用保留节点信息并标记待处理。需要启动 DCC 时，仅对用户明确选择的可信工程运行，并使用普通桌面账号。 [SideFX Archive Project](https://www.sidefx.com/docs/houdini/nodes/top/labs--archive_project-1.0.html)
3. **应用过滤规则。** 默认保留工程、项目内被引用的依赖和选中的主预览。明确的版本控制目录（如 `.git`）、系统垃圾文件（如 `Thumbs.db`）及未被引用的自动备份、日志可默认排除。缓存、渲染和贴图按模板需求勾选，不能仅凭 `cache` 或 `render` 目录名自动删除。用于恢复的生产依赖优先于默认排除规则，未知文件和明确排除的依赖在预检中逐项说明。
4. **确认发布。** 用户确认保留列表和主入口。目录外依赖经确认后复制到包内，并为包内外所有写死的绝对路径记录映射。内置适配器在暂存区改写工程副本为可移植路径，或为目标软件配置可复现的项目根。依赖原机环境变量且无法确认值的引用显示为待修复。复制时流式计算哈希并校验，完成后登记不可原位覆盖的版本。扫描后发生变化的文件重新确认或重扫。源工程继续留在用户的制作目录。

用户可以维护一套默认路径和扩展名过滤规则，单次导入仍可覆盖。预检给出定量结果，例如「保留 12 GB · 排除 43 GB · 2 个外部依赖待处理」。未识别到工程入口时允许指定入口或取消导入。首版跳过重解析点、符号链接和目录联接，路径清单中发现被依赖的链接时要求用户选择真实文件。

## 5. 素材存储与版本

**模板名用于搜索，UUID 用于存储。** 新模板和每个版本分别分配稳定 UUID，实体主键和目录路径都不依赖项目名、镜头编号或模板标题。用户可改显示名。原项目、原镜头名和来源文件名是可查询的来源信息。即使两个项目都有 `EP04_seq01_sc073a`，正常导入也各自创建独立模板。只有用户明确选择「导入为现有模板的新版本」时才关联已有模板；跨库导入遇到相同模板 ID 时检查版本和内容，避免覆盖。

新入库的工程使用 `abc/`（模型、动画和相机缓存）、`tex/`（贴图）、`hdr/`（天空球）、`hda/`（Houdini 自定义节点）、`render/`（渲染序列）。标准目录保留其内部子目录和原文件名，`geo/` 等识别出的缓存目录归并到 `abc/`。自定义目录如 `add_file/` 默认待勾选，勾选后按原相对路径拷贝。清单记录调整过的源路径与归档路径。有路径变化时，预检提醒检查并重连工程引用。

机器存储路径使用 `templates/<模板UUID>/<版本UUID>/project/`。对外导出文件名可用「模板显示名 + 版本 + ID 短码」，发生重名时保护现有文件。包内保留完整 UUID。

```text
template-library/
  templates/<模板ID>/<版本ID>/project/
    fx/fire.hip
    abc/fire.abc
    render/fire/fire.1001.exr
    render/fire/fire.1002.exr
    textures/fire_mask.1001.exr
    review/fire.mov
  derived/<版本ID>/
    cover.webp
    preview.mp4
  staging/<任务ID>/
```

- **MOV** 保留原文件和原相对路径。浏览时播放生成的兼容代理，必要时也提供打开原 MOV。含 alpha、HDR 或特殊编码的 MOV 用代理展示时应标识转换策略，保留原始媒体供交付和复用。
- **EXR** 序列按原目录逐帧保存。数据库维护序列摘要和逐文件记录，界面按组浏览。打包只读取所选版本的文件清单，解包仍恢复同样的序列路径。
- **新版本** 复制或生成到新版本目录，旧版本保持可追溯。先以原结构和完整性验收。文件哈希首版用于校验和查找重复，跨版本物理去重等到实际空间数据表明有收益，再评估实现。
- **写入一致性** 暂存和最终归档在同一卷。文件校验并完成目录切换后，数据库事务才标记版本可见。发生中断时，启动后按任务记录核对未提交目录，再重试或清理。导出中的版本受保护，清理旧版本前检查引用和导出任务。

## 6. 导入后的大小优化

设计独立的「优化大小」任务。用户可选整个版本、部分序列、图片或视频。先展示文件用途、可选处理方式和抽样前后体积，确认后批量运行。压缩结果先写到暂存区，再生成预览或一个独立的优化版。要真正回收原素材占用，须在验收后根据版本保留策略清理旧版，界面分别显示预计节省与当前总占用。

| 素材用途 | 默认策略 |
| --- | --- |
| MOV 或其他预览视频 | 生成兼容的 MP4/H.264 代理，例如 720p 或 1080p，不放大原片，保留画幅和时长。可指定精简包使用原 MOV，或经显式选择后使用兼容的低码率 MOV。 |
| 展示用参考图 | 生成限长边的 WebP 或 PNG。对含透明度的预览保留 alpha，封面和代理可以按需重新生成。 |
| 仅展示用 EXR 序列 | 使用项目 OCIO 配置生成代理。若下游仍需要逐帧预览，可生成低分辨率 EXR 副本；保持帧编号、帧范围和文件名。 |
| 工程引用的普通 EXR | 首先比较同精度的无损 ZIP/PIZ。确需降分辨率时按选定序列创建优化版本，先看样帧，再验证完整序列与 Nuke/Houdini 的读取和效果。 |
| 多层、Deep、数据通道 EXR，以及生产贴图 | 自动降分辨率跳过，包括 Z、运动矢量、Cryptomatte、法线、位移、遮罩及未知用途文件。它们可单独生成用于查看的代理，原始工程输入按其数据语义处理。 |

优化应区分**代理**和**可复用工程输入**。生成代理只写派生目录。生成完整优化版本时，启动前显示临时空间峰值、保留旧版所需空间和清理旧版后的预计占用。对 EXR 无损转码比较像素值、通道及类型、部件、图像窗口和相关元数据。对明确允许降分辨率的版本另外校验尺寸变更、帧数、透明度及工程实际结果。预览按项目指定的 OCIO 显示变换生成，缺少可靠色彩空间信息时由用户确认。视频校验时长、音频和画幅，序列转换失败或体积没有改善时报告结果。 [OpenEXR 压缩与通道](https://openexr.com/en/latest/TechnicalIntroduction.html) · [FFmpeg 缩放](https://ffmpeg.org/ffmpeg-filters.html#scale)

## 7. 数据与检索

| 数据实体 | 主要字段和规则 |
| --- | --- |
| 模板、版本 | 稳定 ID、标题、说明、软件、入口工程、当前版本、版本来源、是否完整。发布一个版本对应一份确定的文件清单。 |
| 文件、序列、引用 | 版本 ID、相对路径、用途、大小、SHA-256、可用状态。序列记录帧集合和缺帧，引用记录工程节点、原路径、映射和解析结果。 |
| 标签、模板标签 | 标签名和规范化名称，允许中文。规范化后唯一，保留用户显示名。关联表用 `(tag_id, template_id)` 索引支持多标签筛选，标签重命名或合并保留关联。 |
| 后台任务、AI 建议 | 类型、目标版本、进度、状态、输出、错误与重试信息。AI 建议记录模型、来源、处理状态及对应标签。 |

搜索优先按标签 ID 匹配，模板名做简单补充查找，列表采用稳定分页。首版用 PostgreSQL 的唯一约束和普通索引，避免双份索引数据的同步负担。筛选速度以真实模板规模验证，发现明确瓶颈后再扩展全文索引。

## 8. 打包、导出和跨设备恢复

| 范围 | 产物 | 恢复行为 |
| --- | --- | --- |
| 仅数据库 | 应用库的 PostgreSQL 自定义格式备份及版本说明 | 恢复模板记录、版本和标签。检测对应素材目录；缺文件的版本显示待补齐。 |
| 单模板精简包 | 工程、预览 MOV、模板元数据及依赖清单 | 作为模板条目导入，可查标签和看效果。缓存、渲染序列、贴图等依赖不随包传输，逐类显示需补齐的内容。 |
| 单模板完整包 | 工程、预览 MOV、所有已归档依赖和模板清单 | 下载或导出为保留目录结构的包。可解包到工作目录复用，或导入另一个模板库。 |
| 完整库备份 | 应用库备份、全库清单及所有已收录版本必须的文件 | 供另一台机器全量恢复，恢复标签、版本、工程和素材关联。可重新生成的封面和视频代理由清单标明，可选择随备份保存。 |

**包格式**使用版本化 JSON 清单和支持大文件的 ZIP64，媒体默认仅打包或使用低压缩。每个包包含格式版本、文件大小、哈希、导出范围和已知缺失项。应用内下载直接流式生成；需要可靠完成的备份先在目标盘写为临时文件，校验后再完成命名。包体超过单个介质容量时，改用同结构目录式备份，复用相同清单和校验流程。

**导出一致性。** 完整库备份开始时进入短暂的库元数据只读窗口，将数据库备份和版本清单固定在同一时点，同时保护该次导出引用的版本目录。数据库备份结束后即可恢复入库和编辑，大文件复制仍使用已经固定的版本。数据库和文件包使用同一个备份 ID。打包中断只留下未完成的产物，重试重新执行校验和写入。

**恢复步骤。** 先读清单，确认版本兼容、可用空间、Windows 路径、帧范围和依赖。检查路径穿越、Windows 大小写冲突、保留文件名和符号链接，再按清单解包并逐文件校验。整库恢复使用受控账号将应用数据库还原到新库，并写入新的素材目录。模板包按数据导入，数据库归档只从可信来源恢复。旧机未完成的任务标记中断，重新生成本地预览索引，按需配置新机凭据和备份位置。全部校验通过后切换库配置，保留原库直到恢复验收。 [PostgreSQL pg_dump](https://www.postgresql.org/docs/current/app-pgdump.html) · [pg_restore](https://www.postgresql.org/docs/current/app-pgrestore.html)

**恢复可用性的判定。** 完整包包含所有已收录的文件。如果某个工程仍有未解析的必需路径、缺少插件或需要额外许可证，导出和恢复报告标为「有缺项」，列出需要补齐的内容。换机验收在原项目盘不可访问、目标根盘符不同的机器上执行，打开 Houdini 和 Nuke 示例工程，验证 ABC、贴图和指定序列帧可以读到。

### 8.1 定时数据库备份

由 Windows 后台服务负责调度。到点使用与应用数据库兼容的 `pg_dump` 导出应用库，先写临时文件，再检查退出状态、归档目录可读性和文件哈希，全部通过后标记成功。关机或休眠错过计划时，下次服务启动补做最近一次，避免同一库并行执行重复备份。支持立即备份，显示最近成功时间、下次运行、备份大小和失败原因。

成功生成新备份后按保留份数清理旧的成功备份。失败保留既有备份，记录错误并提示重试。备份目录建议放在另一块物理盘，检测写入权限和可用空间。定时备份只涵盖应用数据库，跨设备还原 ABC、EXR、贴图和 MOV 仍需匹配的素材备份，或定期手动生成完整库备份。验收时用定时生成的备份恢复到空库并随机抽查模板、版本和标签。 [PostgreSQL 备份说明](https://www.postgresql.org/docs/current/app-pgdump.html)

## 9. AI 图片与视频标签

把 AI 接入为一个可选的后台分析模块。输入为某个版本的封面、用户选择的图片，或从 MOV/预览代理均匀抽取的关键帧；首版也允许用户丢入一段视频，先给出标签建议后关联到模板。定义统一的分析输入和 JSON 输出，后续可接本地视觉模型或外部服务。

- 对模型提供已有标签和可选类别，例如效果类型、元素、风格。模型返回候选标签、置信度和相关画面或时间点。应用先做名称规范化，与词库匹配，未命中的进入新标签建议。
- 用户可批量接受、修改或拒绝建议。后续分析保留已人工确认的标签，不重复生成同一批建议。只有经过接受的标签进入模板主筛选。
- 默认关闭外部传输。开启云模型时由用户决定可发送的预览或抽帧，工程文件、生产素材和本地绝对路径不作为模型输入。模型结果只作为数据处理，AI 模块没有文件改写、发布或执行命令的权限。

## 10. 实施顺序和验收

| 阶段 | 实现 | 验收 |
| --- | --- | --- |
| 1. 目录导入与浏览 | 首次配置、桌面端、本地服务、受保护目录、多入口导入、版本、标签和基础封面及视频预览 | 以附件结构测试分别拖入目录、HIP、NK 和 MOV 都能找到同一套候选文件。导入两个同镜头名的项目，确认独立存储且都能按中文标签搜索。验证桌面账号无法直接写归档目录。 |
